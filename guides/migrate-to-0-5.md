# Migrate to 0.5

Emporium 0.5 does not update apps that 0.4 installed. The configuration model changed, and 0.5 carries no
backward compatibility code. After you upgrade Emporium, every 0.4 app keeps running but shows the state
`NEEDS_MIGRATION`. The only action the panel and the API offer on it is **uninstall**.

To move an app to 0.5, you uninstall it and install it again from the 0.5 chart. If the app has data, you
back the data up first and restore it into the new app.

## What changes for an app

| 0.4 | 0.5 |
|---|---|
| Namespace chosen at install | A new namespace `emp-<name>`, created and owned by Emporium. The old namespace is not touched and not reused |
| Bundled database in the app chart | A CloudNativePG cluster `<name>-<integration>`, created by Emporium. The data moves by dump and restore |
| Passwords in the config Secret or generated by the chart | The app Secret `<name>-emporium-secrets`. Values you carry over are passed in the install |
| Login through the old OIDC client | A new OIDC client. Users sign in again; their accounts are unchanged |
| Same host name | The same host name, once the old Ingress is gone |
| Event history | Not migrated. The new app starts with empty events |

## Before you start

- Upgrade Emporium itself first, with `helm upgrade` and not with the in-app system update.
- Check that the app's chart has a 0.5 version in your repository. Charts that were not converted to
  `emporium.yaml` cannot be installed in 0.5.
- Plan a maintenance window. The app is unavailable while its data moves.
- Have `kubectl` and `helm` access and an Emporium admin token.

## Apps without data

Uninstall the app in the panel, then install the 0.5 version with the settings you used before. Take the
old settings from the app's config before you uninstall.

## Apps with data

Follow the blueprint
[Migrate an installed app from 0.4 to 0.5](https://github.com/monostream/emporium/blob/main/docs/blueprints/migrate-installed-app-to-v0.5.md).
It is written for an operator or an AI agent and migrates one app at a time:

1. Inventory the app and stop everything that writes.
2. Take a verified backup: a database dump with row counts, copies of the volumes, and the Kubernetes and Helm state.
3. Protect old volumes so that `helm uninstall` does not delete them.
4. Preview the 0.5 install, uninstall the 0.4 app, and install the 0.5 app **on hold**. On hold, Emporium
   creates the new database and installs the app with every workload scaled to zero.
5. Restore the dump and the volumes into the new app and compare row counts.
6. Release the hold, verify the app with a person who knows the data, and clean up only after they confirm.

Rollback is described for each phase. After the uninstall there is no Helm rollback, so the blueprint
reinstalls the old chart from the backups made in step 2.

## Keeping data on uninstall in 0.5

The migration relies on one 0.5 feature that you can also use directly: uninstalling an app with "Keep data".
The data is not deleted but marked as retained, and a reinstall under the same name is refused until the
retained object is deleted. See [Retained data](./providers#retained-data).

## Chart authors

Convert your chart with the blueprint
[Migrate a chart to `emporium.yaml`](https://github.com/monostream/emporium/blob/main/docs/blueprints/migrate-chart-to-emporium-yaml.md)
and use the [`emporium.yaml` reference](../reference/emporium-yaml).
